Configuration

XML config, before and after

The build kept failing to parse — the file below has three separate well-formedness violations.

✕ found in repo
<?xml version="1.0"?>
<config>
  <Setting name="theme">dark</settingTag names are case-sensitive in XML. <Setting> and </setting> don't match, so this element is malformed.>
  <setting name="timeout">30Opened but never closed — there's no matching </setting> here before the next element starts.
  <setting name="retry" value="3&4A bare "&" is not valid inside an XML attribute value — it must be escaped as &amp; or the value quoted differently."/>
</config>
✓ corrected
<?xml version="1.0" encoding="UTF-8"?>
<config>
  <setting name="theme">dark</setting>
  <setting name="timeout">30</setting>
  <setting name="retry" value="3&amp;4"/>
</config>
Well-formed XML: matching case, closed tags, escaped entities
Transport

Running over the right protocol

Every request in Lumen — page loads, the registration POST, API calls — goes over one protocol only.

http://lumen.app

Unencrypted. Anything sent — including the registration form above — would be readable by anyone on the same network. No padlock, and most browsers now flag it as "Not secure."

https://lumen.app

HTTP layered over TLS. The request and response bodies are encrypted end-to-end, the server's identity is certificate-verified, and the padlock in the address bar reflects that.

HTTPS = HTTP + TLS — the correct protocol for anything handling user data
